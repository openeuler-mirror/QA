## 3.2   约束说明

1. 仅支持小模型混部场景，即多个小模型使用同一张NPU卡；
2. 仅支持NPU卡，且不支持设备动态插拔场景，各个型号NPU卡需要进行适配；
3. 最低支持 1MB 显存申请；
4. NPU 驱动向 dmem 注册显存信息时，因为 NPU 采用的是多线程并发注册，所以注册的信息可能不会按照设备 id 从小到大显示，而社区的 amdgpu 驱动向 dmem 注册时是按照设备 id 从小到大遍历注册，这个问题会遗留到驱动免修改的方案里去处理。
5. 如果同时开启了 CONFIG_CGROUP_XCU 和 CONFIG_CGROUP_FREEZER，无论 cgroup v1 和 v2 都可以通过 cmdline 配置 cgroup_disable=xcu 或 freezer 关闭 xcu 或 freezer 子系统，但 INFO 日志只会显示 "cgroup: Disabling xcu control group subsystem"；dmem 和 cpuacct 子系统类似。
6. 如果错误配置 xcu cmdline 和 cgroup 的挂载方式，会导致子系统不可用，例如 xcu=enable，systemd.unified_cgroup_hierachy=0（cgroup 以 v1 挂载），此时 freezer cgroup 子系统不可用，并且会打印 "XCU cgrp is incompatible with the cgroup version" 的 warning 日志；xcu=disable，systemd.unified_cgroup_hierachy=1（cgroup 以 v2 挂载），此时 freezer 和 xcu cgroup 子系统都不可用，freezer 子系统不支持 cgroup-v2，echo +xcu > cgroup.subtree_control 会失败，并提示 "Operation not permitted"。
7. xcu cgroup 子系统仅支持 cgroup-v2，如果 CONFIG_CGROUP_FREEZER=n 并且以 v1 形式挂载，xcu cgroup 子系统不可用。
8. cgroup-v2 时 cat /proc/cgroups 时会显示 freezer 而没有 xcu，因 /proc/cgroups 在 v2 时是无意义的，v2 使用 cgroup.controllers 替代，cgroup.controllers 会正常显示 xcu。
