# 1     特性概述

TrustRuntime是CMS签名验签服务，部署于机密计算虚机（Confidential VM）中，以systemd托管进程形式运行，通过vsock对外提供三类安全通信接口：

1. **签名接口（0x10→0x11）**：输入原始数据，使用ECC-256算法计算CMS签名值，返回签名数据和本地证书Subject Key ID。
2. **验签+签名接口（0x12→0x13）**：先验证输入签名数据的有效性（证书链+CRL+签名匹配），验签通过后使用输入证书ID对新数据进行签名。
3. **验签接口（0x14→0x15）**：验证签名数据是否有效，并判断证书身份（本节点签名/其他节点签名/证书身份冲突）。

通信层采用TLS over vsock双向认证，确保传输链路安全。服务为无状态签名服务，不持久化业务数据。支持PEM/DER双格式证书自动识别、CRL证书吊销校验、证书过期巡检等安全机制。

## 3.2   约束说明

1. 特性使用时涉及到的约束及限制条件：
   - 证书路径已硬编码，通信证书需放置于`/etc/cert/server/`，签名证书需放置于`/etc/cert/cms/`
   - 仅支持ECC-256签名算法，不支持其他算法（如RSA、ED25519等）
   - 最大16个并发vsock连接（Semaphore限流），超出连接排队等待
   - 单条消息最大10KB，超过返回协议错误（type=0x02）
   - 证书不支持热更新，更新证书需重启服务
   - systemd资源限制：CPUQuota=10%，MemoryMax=30MB
   - SSL握手超时5秒，空闲连接超时60秒
   - Release构建仅允许info/warn/error日志级别

2. 特性依赖均在openEuler社区范围内依赖自闭环：
   - Linux内核 >= 4.8（vsock支持）
   - OpenSSL >= 1.1.1（TLS通信、CMS签名验签）
   - systemd（服务管理）
   - glibc >= 2.17
   - 以上依赖均在openEuler 24.03 LTS SP3仓库中默认提供
