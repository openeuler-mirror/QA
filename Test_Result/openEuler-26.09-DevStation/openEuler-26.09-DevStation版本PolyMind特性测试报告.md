**关键词**：PolyMind，AI Agent，定时任务调度，IM 机器人，Agent 模版，RPM，Electron

**摘要**：PolyMind 是自托管的 AI Agent 交互平台，前端为 Next.js 应用，后端为 witty-service（FastAPI）。本版本交付四类特性能力：(1) 定时任务调度，支持按 cron/周期自动执行 agent 任务并提供完整执行记录；(2) IM 机器人集成，支持企业微信机器人扫码或手填凭据接入，把私聊消息路由到 agent，并以准入策略控制可驱动范围；(3) 默认 Agent 模版，把 openEuler 场景下的日志诊断、安全 CVE、集群容器、性能调优等 agent 配置打包为包内模板，一键实例化；(4) openEuler 生态集成，桌面端应用以 RPM 交付，采用 Electron 自包含形态，不依赖 nginx 与 Node 服务端。同时交付会话与对话、智能体管理、模型与技能市场等基础能力。

本报告覆盖上述需求的特性测试（功能、接口异常与边界、鉴权、交付物结构）与资料测试，共计执行 42 个用例，全部通过；

# 1 特性概述

PolyMind 平台提供以下基本能力：

(1) **定时任务调度**：内置任务模板库（如"每日竞品动态追踪"），支持按 cron 表达式或固定周期创建任务，任务绑定执行智能体并按时区调度；后端调度器负责注册与触发，同一任务同一时刻只允许一次在飞运行（重复触发登记为 skipped），执行结果以运行记录（running/succeeded/failed/skipped）与会话双记录沉淀，支持启停、部分更新、手动立即执行与跨任务执行记录分页查询。

(2) **IM 机器人集成**：提供企业微信机器人接入能力，包含渠道目录（渠道标识符、凭据字段、能力边界）、扫码接入（平台授权自动建机器人，begin/poll/cancel 三态）与手填凭据两条通路；实例支持绑定/解绑 agent、重连、连通性测试（delivered/rejected 三态）与删除；准入策略按单聊/群聊分别配置（默认放开，可切换白名单），写入后立即生效；凭据以 0600 文件存储，任何接口只回传掩码。

(3) **默认 Agent 模版**：包内预置多套 agent 模板（集群与容器、日志与故障诊断、OS 层性能调优对照、oeAware 应用/OS 层性能优化、安全与漏洞治理、系统生命周期管理等），模板元数据声明技能集、MCP 服务与默认使用提问；`GET /agent-templates` 只读扫描（零网络、零 DB），`POST /agent-templates/{name}/instantiate` 一键实例化，遵循"一模板一实例"并在任一步失败时整体回滚。

(4) **openEuler 生态集成**：桌面端应用以 RPM 交付（`polymind.spec` + 源码包），采用 Electron 自包含形态——主进程以 `app://` 托管静态前端产物，`/api` 由主进程代理到本机 witty-service，不再需要 nginx 与 Node 服务端；后端 witty-service 作为独立 RPM 依赖，Electron 预编译产物校验和钉死在 spec 中，运行库依赖显式声明。

(5) **基础能力**：会话与对话（列表/详情/新建/重命名置顶/删除/事件与消息）、智能体管理（创建/暂停/恢复/删除、运行时能力发现）、模型与技能市场（模型配置增删改查、技能仓库同步与技能清单）。

## 3.2 约束说明

1. 测试环境为单机部署：witty-service 监听 127.0.0.1:8000，鉴权令牌为测试环境令牌；生产部署需另行配置模型密钥与访问控制。
2. 定时任务在绑定智能体时必须指向已存在且存活的 agent，测试使用环境内已实例化的模版 agent 作为载体。
3. IM 机器人集成：企业微信机器人的真实凭据不在测试环境内，因此连通性相关用例验证的是**设计语义**（未连上返回三态 rejected 而非 5xx），真实消息投递与回合链路需在具备有效凭据的环境补测。
4. 特性依赖(FastAPI、Uvicorn、SQLAlchemy+Alembic、APScheduler、Node.js 22、Next.js 16等) 均为开源组件并公开可获得，依赖自闭环，无闭源二进制依赖。

## 4.3 DFX专项测试结论

### 4.3.1 性能测试结论

性能数据取自可复跑基准集 `tests/e2e/test_performance.py`（7 条，`python3 -m pytest test_performance.py -v -s`，本次 14.15 s 全绿）；测量环境为被测环境同机（4 vCPU 虚拟机，仅运行 witty-service 服务端进程），并发以 barrier 同步起跑、分位数取最近秩法（不插值）、吞吐 = 总请求数 ÷ 总墙钟时间。

| 指标大项 | 指标小项 | 指标值 | 测试结论 |
| --- | --- | --- | --- |
| API 基准性能 | 任务模板目录 / 渠道实例列表 单请求响应时间（P50，n=5） | 2.3 / 1.8 ms | 通过 |
| API 并发性能 | 轻量读接口 100 并发响应时间（P95 / P99） | 751 / 875 ms、712 / 781 ms（阈值 < 1000 ms） | 通过 |
| API 并发性能 | 轻量读接口 100 并发错误率 / 吞吐 | 0% / 177~199 req/s | 通过 |
| API 并发性能 | 轻量读接口 P95 放大幅度（P95 ÷ 单请求基线） | 329× / 389×，吞吐饱和于约 180 req/s | 通过 |
| API 聚合接口性能 | 任务列表 `include_runs=20` 50 并发响应时间（P95 / P99） | 324 / 340 ms（阈值 < 500 ms） | 通过 |
| API 聚合接口性能 | 任务列表聚合接口 50 并发错误率 / 吞吐 | 0% / 164 req/s | 通过 |
| 分页性能 | 执行记录 `limit=20`，offset 0 / 100 / 500 / 1000 响应时间 | 4.14 / 4.05 / 3.87 / 4.07 ms（最差 / 最优 1.07×） | 通过 |
| 流式会话性能 | 一轮对话 建连 / 首 token / 整轮耗时 | 65 / 629 / 668 ms（阈值首 token < 30 s） | 通过 |

说明：上表阈值为本环境实测标定值，用于发现回归，不作为 SLA；本轮未开展长时间稳定性压测与容量上限探测，技能市场接口的分页改造与轻量接口的并发水位建议见 5.2。
